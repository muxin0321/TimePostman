# TimePostman 手机端（双向互传最小闭环）

功能：

1. 选择手机照片，上传到电脑的 `phone-inbox/`；
2. 刷新电脑处理结果；
3. 下载处理后的文件，用系统 SaveButton + `createAsset` 批量保存到图库。

## 已验证

- `SaveButton` + `createAsset` 的单文件保存路径已在 Mate 70 Pro+ / HarmonyOS NEXT 真机验证：测试图 EXIF 日期 2020-01-02 12:00，保存后系统图库显示 2020-01-02 12:00。
- **2026-10-22 双向闭环验证通过**：手机上传 → 电脑改日期 → 手机刷新/下载 → SaveButton 批量保存，图库日期正确。
- **2026-10-22 11 张批量验证通过**：一次上传 11 张成功，手机端一次保存全部成功。SaveButton 临时授权窗口对 11 张小图够用；更多张失败时可保留重试。
- **2026-10-23 扩展名修复 + 18/18 通过**：批量 18 张里 13 张成功、5 张失败；失败项实际是 JPEG 内容被 URI 后缀误命名为 `.png`。手机端现在读取文件头判断 JPG/PNG/HEIC 再命名；PC 端也会归一化输出扩展名。5 张重传后全部成功，18/18 通过。MakerNote 警告是良性提示，成功项不再展示。

## 准备

- DevEco Studio 6.0
- Mate 70 Pro+ / HarmonyOS NEXT，开启开发者模式和 USB 调试
- 项目根目录开两个终端：

```bash
# 终端 1：电脑端日期编辑器
npm run app

# 终端 2：手机互传服务（8787）
npm run phone:transfer
```

## 首次配对

- 手机和电脑在同一 Wi-Fi：打开电脑页面 `http://127.0.0.1:4317`，手机 App 点“发现电脑”，选中电脑后点“配对”。
- USB 测试：先运行 `hdc rport tcp:8787 tcp:8787`（`npm run start:all` / `start.bat` 会在检测到手机时自动设置），手机 App 手动输入 `127.0.0.1`，点“用 IP 配对”。已配对后也可以直接点连接卡片里的“USB 直连”切到 `127.0.0.1`，速度通常比 Wi-Fi 快；标签会显示当前是 USB 还是 Wi-Fi。
- 电脑页面顶部会显示 6 位配对码；在手机 App 输入并确认。
- 配对成功后双方保存 token，下次自动连接；App 里的“重新配对”可以清除连接。
- 自动发现使用 UDP `8786`；如果路由器 AP 隔离或防火墙导致发现不到，用手动 IP 兜底。

## 安装 / 运行

Signed HAP 已构建：

```
entry/build/default/outputs/default/entry-default-signed.hap
```

手机连接并解锁后，可以用 DevEco Studio 点 Run，或：

```bash
hdc install -r entry/build/default/outputs/default/entry-default-signed.hap
```

如果出现 `no signature file`，确认 `build-profile.json5` 的 product 里有 `"signingConfig": "default"`；DevEco 自动签名生成的材料在 `C:\Users\<用户>\.ohos\config`。

## 使用

1. 打开 App（桌面标签“TimePostman 接收测试”，界面标题“TimePostman 双向互传”）。
2. 首次连接：按上面的“首次配对”完成配对；配对后 App 会显示“已连接”。
3. 点“选择照片/视频并上传”，一次最多选 50 个，单个文件上限 300MB。建议先测 10-20 张 JPG；批量压测可直接选 30-50 张。
4. 到电脑上打开 `http://127.0.0.1:4317`，点“手机传入”，电脑只会扫描本次最新上传的一批，旧批次不会混进来。
5. 设置目标日期并处理。目标日期默认等于当前日期，记得点“应用到已选”或改单行日期。
6. 回到手机 App，点“刷新结果”。互传服务只显示本次上传之后生成的输出，旧批次不会串进来。
7. 点“下载全部结果”，再点系统“保存”按钮。保存按钮就在“刷新结果 / 下载全部结果”下面，不需要滑到列表底部。一次会保存全部待保存文件；如果状态显示“失败 N 个”，再点一次系统保存按钮重试失败项。
8. 到系统图库检查日期。

所有文件都走单流批量上传/下载；USB 直连更快也更稳定。上传和下载都走缓存文件分块读写，不会整段读进内存；上传结束后自动清理临时文件。

每批新上传会先写入临时目录，全部接收成功后再替换 `phone-inbox/` 里的上一批；上传失败时旧批次保持不变。因此重复上传同名文件（例如 `鼠标1.jpg`）仍会保留原名，不会变成 `鼠标1-2.jpg`。只有同一批里出现重名时才会加序号。

## 注意事项

- 批量保存用的是 SaveButton 的临时授权窗口（约 10 秒）。App 会一次尝试保存全部；超时失败的文件会保留，再点一次系统保存即可重试。
- 编译时的 `WRITE_IMAGEVIDEO` 警告是正常的，SaveButton 会提供临时授权。
- 目前 JPG 和 MP4 视频保存已真机验证；MOV、HEIC、PNG 还未真机验证。
- 互传服务现在只接受配对令牌，旧版硬编码测试 token 已移除。
- GIF/WebP 真机确认图库不采用内嵌日期，App 会在上传前自动跳过并提示；需要改日期请先转成 JPG/PNG。
- 上传失败：确认两个 PC 服务都在运行、已配对成功、USB 反向端口已设置或手动 IP 正确。
- 保存失败：把 App 里的错误文字发我；如果是权限/授权问题，需要换保存策略或拆分批次。
